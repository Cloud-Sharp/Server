# CloudSharp 유즈케이스 테스트 우선 작성

## 테스트 작성 스킬 연결

이 스킬의 산출물은 `ExecuteAsync`의 기대 동작을 검증하는 NUnit 테스트 코드와 그 검증에 필요한 Core 포트 계약이다. 업무 로직과 Infrastructure 어댑터 구현은 후속 범위다.

테스트 코드를 작성하거나 수정하기 전에 [aspnet-unit-testing](../../../.claude/skills/aspnet-unit-testing/SKILL.md)을 읽고, NUnit 이름·케이스 구성·단언·테스트 데이터 작성 규칙을 적용한다. 파일이 없는 체크아웃에서는 저장소 루트의 `CLAUDE.md`에 있는 Unit tests 규칙과 인접 Core 테스트를 따른다. 패키지와 API는 현재 테스트 프로젝트의 설정을 기준으로 한다.

업무 로직이 미구현인 상태에서 테스트 우선 작업을 요청받았다면, `aspnet-unit-testing`의 전체 통과 기준에는 이 스킬의 예상 실패 기준을 적용한다.

## 계약과 테스트 진입점

- 저장소 루트의 `CLAUDE.md`, 대상 유즈케이스의 설계 문서, Command·Query, validator, 결과 DTO, 도메인 메서드와 Core 포트를 읽는다. `docs/use-cases/space-use-cases.md`의 ID처럼 설계가 진입점을 가리키면 해당 핸들러와 인접 픽스처를 대조한다. 설계와 코드가 충돌하면 테스트가 어떤 계약을 기준으로 하는지 명시한다. 무변경 요청의 버전 확인 시점처럼 업무 동작을 바꾸는 미결정 사항만 확인한다.
- `tests/CloudSharp.Core.Tests/UseCases/` 아래 해당 기능의 픽스처에서 실제 `ExecuteAsync`를 호출한다.
- 성공 결과와 비즈니스 오류의 **목표 동작**을 직접 단언한다. 미구현 골격의 `NotImplementedException`은 실행 결과에서 예상 실패로 확인한다. 골격의 예외 자체를 단언하는 스모크 테스트는 별도 목적이다.

## 테스트 데이터와 의존성

- 실제 도메인 객체, 고정 UTC 시각, 요청 범위의 인가 컨텍스트를 사용한다. 가능한 경우 실제 인가 정책으로 컨텍스트를 만들고, 인가 후 상태·소유권·버전이 바뀌는 케이스에서는 인가에 사용한 스냅샷과 포트가 반환하는 최신 스냅샷을 따로 준비한다.
- 기존 `tests/TestSupport/Fakes/`의 저장소, Unit of Work, 트랜잭션, `FakeClock`을 재사용한다. 픽스처 한 곳에서만 필요한 호출 기록이나 실패 주입은 해당 픽스처의 작은 더블로 둔다.
- 기존 Core 포트를 우선 재사용한다. 기존 계약으로 검증에 필요한 의존성을 표현할 수 없으면 최소한의 포트 인터페이스와 필요한 입출력 타입을 작성한다. 주입 경계가 필요한 경우 내부 의존성 생성자를 추가한다. 기존 `InternalsVisibleTo`를 활용하고 공개 생성자 및 API DI 해석을 보존한다. 테스트 우선 단계에서 핸들러는 기존 검증을 수행하고 유효한 입력은 미구현 경로로 진행한다.

## 동작 단언

- **입력 검증**은 기존 `ErrorCode`와 `PropertyName`, 조기 거부 시 의존성 미호출을 검증한다. **업무 검증**은 최신 상태·소유권·관계, 도메인 오류, 포트 실패를 통해 해당 유즈케이스가 맡는 판단을 검증한다.
- **조회**는 인가된 식별자로 최신 데이터를 읽고 결과 DTO에 PublicId·현재 버전·유효 권한을 계약에 맞게 반환하는지 확인한다. 목록에서 유즈케이스가 접근 제어와 페이지 제한을 맡으면, 더블에 접근 불가 항목도 넣어 필터링 후 페이지를 채우는지 검증한다.
- **변경**은 변경 결과와 보존할 값, 조회 시 관찰한 이전 버전으로 변경을 등록하는지 확인한다. 조회 시 버전 불일치와 저장 중 동시성 충돌을 각각 재현한다. 여러 쓰기가 원자적으로 반영되어야 하면 저장 전에 모두 등록되는지, 중간 실패 시 후속 쓰기와 저장을 중단하고 롤백하는지 검증한다.
- **무변경 성공**은 계약에서 요구하는 버전 검사를 거치고 버전과 수정 시각을 보존하는지 확인한다. 등록·저장·커밋·롤백은 독립적으로 단언한다. 쓰기가 0회여도 읽기 트랜잭션은 커밋할 수 있으므로 쓰기 단언 헬퍼에는 커밋 횟수를 넣지 않는다.
- 포트 호출은 업무 계약에 의미 있는 경계만 고정한다. 호출을 기록하는 더블은 등록·저장·커밋·롤백 요청을 검증한다. 실제 DB 반영, cascade와 트랜잭션 원자성은 해당 영속성 통합 테스트에서 검증한다.

기존 사례는 `GetSpaceQuotaUseCaseTests`의 최신 조회, `UpdateSpaceUseCaseTests`의 생략·명시적 null·무변경 수정, `TransferSpaceOwnershipUseCaseTests`의 다중 변경과 롤백을 참고한다. 사례의 권한·오류·저장 정책은 대상 유즈케이스의 계약에 맞춰 선택한다.

## 실행과 완료 기준

저장소 루트에서 새 픽스처를 필터로 실행한다. 여러 픽스처는 `|`로 결합하고 `<FixtureName>`은 실제 클래스 이름으로 바꾼다.

```powershell
dotnet test tests/CloudSharp.Core.Tests/CloudSharp.Core.Tests.csproj --filter 'FullyQualifiedName~<FixtureName>'
```

미구현 상태에서는 빌드 성공, 테스트 발견, 기존 입력 검증의 통과, 업무 테스트의 예상 실패를 확인한다. 컴파일·준비·검증 실패는 원인을 확인하고 수정한다. 공유 더블이나 Core 골격을 건드렸다면 관련 기존 테스트를 별도 필터로 실행한다. 최종 보고에는 작성한 테스트, 추가하거나 재사용한 Core 포트, 실제 테스트 실행 결과와 예상 실패의 원인을 적는다.
